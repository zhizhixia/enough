# 示例：现有代码库增加功能——只借鉴，基于现状扩展

> **v0.1 历史材料。** 本例保留当时的外部调研。v0.2 处理已有代码库的局部扩展时，先检查本地模块、依赖、接口、测试和既有决策；只有确有“采用还是自建”的选型时才外部搜索。

## 输入（用户请求）

"给现有的 Python 量化决策项目增加'策略对比'功能：在同一标的上比较多组策略配置的决策结果和差异原因。"

## Enough 的输出（简化自真实运行）

### 复用决策

- 目标：同一标的上多组策略配置的决策对比与差异解释
- 搜索范围：GitHub 仓库搜索（产品场景、技术栈、中英同义词），涉及回测框架与可解释性库约 15 个候选
- 搜索限制：未本地运行任何候选，证据等级为 E1/E2

| 候选 | 核心匹配 | 主要缺口 | 结论 |
| --- | --- | --- | --- |
| 回测框架（vectorbt / backtrader / Hikyuu） | 多策略并排指标 | 都是历史回测框架，与本项目"模型预测 → 规则矩阵"的决策链不匹配 | 不采用 |
| 可解释性库（SHAP 类） | 特征归因 | 适用于黑箱模型归因；本项目是规则矩阵，引入收益低、依赖增 | 不采用 |
| 策略对比报告类项目 | 指标组织方式 | 依赖重，与现有数据管道冲突 | 只借鉴交互与报告思路 |

- 推荐：**只借鉴，不采用**
- 理由：现有决策链是"预测 → 趋势/风险分析 → 规则矩阵 → 决策报告"，与所有候选架构不匹配；基于现有引擎扩展成本更低
- 下一步：先完成代码考古（见下），再做设计确认

### 现状快照（代码考古）

- 数据流：`POST /api/decision-report` → `DecisionEngine.predict_and_analyze` → 数据获取（三级降级）→ 模型预测（多路径采样）→ 信号分析 → 决策报告
- "策略"的现有可调维度：模型选择、采样参数、信号阈值
- 既有规范：中文注释与文档、函数行数上限、决策层异常兜底；测试覆盖决策与数据层
- 工作区状态：有未提交修改和未跟踪文件——均为用户已有改动，保留不动
- CodeGraph：仓库无 `.codegraph/`，建议执行 `codegraph init` 并等待用户确认；拒绝则降级使用文档、Git、测试和 `rg`

### 阻断问题（一次一个）

"策略对比"有三种实现形态，推荐第一种：

- **A. 同股多策略即时对比（推荐）**：同一股票上并行运行多组策略配置，并排展示信号与理由，用归因解释差异来源。完全复用现有引擎，改动最小。
- **B. 策略历史绩效回测对比**：需要引入回测设施，等于新建子系统，工作量大。
- **C. 多股票横向对比**：属于"股票比较"而非"策略比较"，解释价值较弱。

## 要点

- "只借鉴"不是放弃复用：复用的是架构模式、报告组织和交互思路，而不是整套代码。
- 先看现有代码再决定：现状快照发现现有引擎已具备扩展点，这是选择自建扩展的关键依据。
- 未提交修改是用户的，保留不动；CodeGraph 初始化必须等用户确认。
