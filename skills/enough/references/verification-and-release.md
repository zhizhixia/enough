# 验证、测试与发布

在实现前，把“需要成立的主张”映射为能支持或否定它的证据。选择最小充分证据：不把弱证据包装成强结论，也不机械执行所有测试层级。

本参考用于 NORMAL 中存在实质证据取舍、需要新增/治理测试，或任何 DEEP 任务。FAST 通常只运行与改动最接近的原生检查或必要冒烟。

## 1. 先确定主张和现有证据

列出：用户可观察结果、不应改变的关键行为、可信失败模式及风险边界。检查已有自动测试、类型检查、构建、启动路径、真实场景和可靠基线。

- 覆盖充分时，复用证据，不新增永久测试。
- Mock、自动测试、构建成功和真实环境验证是不同强度的证据，必须分别说明。
- 有真实跨边界系统时，优先证明最小纵向闭环：可控输入经过关键 UI、API、进程、存储或设备边界，产生可观察结果与持久化状态。
- 闭环未通过前不扩大并行；Mock 可辅助局部开发，但不能证明真实集成契约。

## 2. 新增永久测试的门槛

只有同时存在下列条件才新增永久测试：可重复的真实故障风险、稳定观察边界、独立预期和持续回归价值。否则选择临时诊断、冒烟、集成运行或可重复人工步骤。

每个新增的重要测试都应能回答：验证哪个公共行为、预期来自哪里、会识别何种可信错误。可在测试名、中文注释或任务证据摘要中留下结论，不必为每个测试另建文档。

### 独立预期

- 预期来自需求、独立真实样例、已知正确结果或明确不变量。
- 不调用被测函数生成 expected；不复制同一算法、分支或错误假设再比较。
- 输入必须驱动真实被测路径；只断言 Mock 返回自设值不构成行为证明。
- 测试观察稳定边界，行为不变的内部重构通常不应使其失败。
- 快照检查具体语义与变化；不能批量接受作为通过手段。
- 调用次数仅在“不得重复提交”等真实契约中有价值；内部偶然顺序不应成为测试目标。
- 类型系统已充分保证的结构不机械复制为运行期测试；跨语言或外部输入边界另行判断。

### 故障识别能力

对重要回归点，优先给出一项低成本证据：旧版本的真实失败、已知反例，或隔离副本中改变关键条件后测试会失败。首次通过不等于无价值，先红后绿也不自动证明高价值；关键是独立预期与识别可信故障的能力。

不得改真实业务工作区制造失败，不使用 Git 重置用户工作区，也不要求每个测试运行变异工具。

### 是否采用 TDD

只有用户明确要求，或行为契约清晰、反例稳定且测试先行有具体收益时，才对指定边界采用红→绿方法。已实现后补的独立行为测试同样有效；不得为了时间顺序删除正确实现重写。请求补集成测试只授权集成测试，不自动扩展为全部实现严格 TDD。

## 3. 既有测试治理

- 默认保留已有测试，并按改动影响运行。
- 仅在本次范围内，确有重复、实现耦合或同义反复时才提议合并或删除。
- 记录原行为主张、低价值依据、仍需覆盖的内容、替代证据及删除后的验证。
- 先判定失败是回归、旧缺陷、环境问题还是失效断言；不得通过删除失败测试达到绿色。
- 不开展无关清理，不把减少测试数作为指标；遵守项目既有覆盖率规则，但不以覆盖率代替验收。

## 4. 按影响选择检查与 DEEP 措施

开发中运行最近改动的相关检查；跨模块、共享基础设施变化或项目规则要求时运行全套。先主流程，再边界和失败路径。

| 风险 | 相称证据 | 不应机械附加 |
| --- | --- | --- |
| 复杂纯逻辑或解析 | 独立样例、不变量、边界测试；可局部 TDD | Canary、真实外部写入 |
| 并发与竞态 | 可控调度、关键时序、重复与取消场景 | 所有外围函数单元测试 |
| 数据迁移 | 脱敏副本演练、前后不变量、恢复方案 | 无授权生产迁移 |
| 认证和隐私 | 权限反例、输入边界、日志脱敏 | 为满足 TDD 删除现有实现 |
| 外部写入 | 最小权限、Dry Run、明确授权、状态查询；适用时 Canary/恢复 | 未授权真实调用、结果不确定时盲重试 |
| 工业设备 | 离线/仿真、人工批准、安全状态与回退 | 为完成验收操作真实设备 |

不可逆操作可能没有真实回滚；执行前必须说明不可逆性和补救方式，不能虚构回滚承诺。凭据只从环境变量或安全存储取得，禁止写入代码、提示、日志、截图或仓库。

## 5. 写入、排错与独立验收

重要本地写入必须以重新读取、差异/哈希或实际运行中的至少一种方式核验落盘。工具报告成功不足以单独构成证据。

同一实现、验证、写入、工具或权限路径连续失败两次后，停止重复尝试；先区分代码、环境、权限与工具故障，再换证据路径或报告阻塞。外部写结果不确定时先查询实际状态，禁止自动重试。

主代理独立检查产物并运行选定验证，不能只复述子代理的完成摘要。每项已批准验收标准都标记为“已验证、部分验证、未验证或不适用”，附命令、输出、截图、构建产物或真实运行证据。必需项仍部分验证或未验证时，只能报告部分完成。

## 6. 发布与停止

发布或部署仅在用户明确授权后进行。发布前按适用性确认：敏感文件与调试数据未混入、项目原生检查/构建、目标环境启动、最小纵向闭环、关键失败路径、迁移/兼容性/恢复、用户可见文档和重要写入落盘证据。

选定验收项证据充分、没有阻断问题且限制已经披露时停止；不要为了“再保险”无限加测试、审查或重构。

```markdown
## 完成结果

- 实现：
- 主要取舍：

## 验收对账

| 验收项 | 状态 | 证据 | 缺口/下一步 |
| --- | --- | --- | --- |

## 验证边界

- 已验证：
- 部分验证：
- 未验证：

## 发布与风险

- 产物/启动方式：
- 已知限制：
- 恢复或补救：
```
