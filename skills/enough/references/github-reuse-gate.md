# GitHub 复用门禁

仅在 `enough` 判定为**真正选型**时加载本参考：新项目、新增重要依赖、引入新的自建能力，或需要在成熟方案与自建之间作取舍。普通本地修复、文案和已有能力的局部扩展不触发本门禁。

目标不是为搜索而搜索，而是在值得比较的情况下找到可直接采用、扩展或借鉴的成熟实现。进入本门禁后，结束调研、暂停或请求确认前必须产出用户可见的复用决策。

## 1. 定义目标

先写清：

- 一句话目标和必须满足的能力。
- 平台、部署、语言/框架及不可妥协约束。
- 隐私、安全、离线、许可证、维护和数据边界。
- 可由配置或小型扩展解决的差异。

只询问阻止有效比较的信息。若已有复用结论，只在平台、必需功能、数据边界、许可证或维护约束发生实质变化时补查受影响候选。

## 2. 搜索与收敛

使用与问题相称的不同查询：产品/场景、核心能力/技术栈，以及必要时同义词、Topics、Awesome 列表、上游或活跃 Fork。优先 GitHub 仓库搜索，按需代码搜索核实关键能力。

初筛和深入核验以足够作出取舍为止，而非追求固定数量。连续两轮不同查询没有新的强候选，或已有候选足以比较时停止扩张。记录范围和限制，不能声称绝对穷尽。

高风险任务加深对最终候选的安全、运行与数据边界核验，不机械增加候选数。

## 3. 评估证据

Star 与 Fork 只是辅助信号。优先核验：

- 必需功能和核心路径是否真实存在。
- 维护活跃度、发布、CI、测试、安装文档与可复现演示。
- 严重未解决问题、许可证、依赖、安全、隐私与目标平台兼容性。
- 配置、迁移、升级和长期维护成本。

仅使用以下证据等级：

- **E3**：实际安装、启动或复现核心演示成功。
- **E2**：有测试、CI、发布或活跃维护等工程证据，但尚未本地运行。
- **E1**：仅 README、截图或作者声明。

E1、E2 不得表述为已本地验证。

## 4. 作出决策

只能明确推荐以下之一：

- **直接使用**：核心结果满足，采用成本和风险可接受。
- **使用并扩展**：主体可用，缺口边界清楚且扩展合理。
- **只借鉴**：整体不适合，但有可复用的架构、交互、数据模型、测试或部署经验。
- **自建**：无合适候选，或采用/迁移风险高于自建。

围绕核心结果、不可妥协约束和总拥有成本说明理由，不用虚假精确百分比代替判断。高匹配候选应明确推荐直接使用，并等待用户决定；先在隔离、可恢复环境试运行，不能立即接入真实凭据或生产数据。

GitHub 不可用或搜索明显不完整时，披露限制。真正选型场景中，未经用户确认不得把不完整调研当作自建依据。

## 5. 输出格式

```markdown
## 复用决策

- 目标：
- 关键约束及变化（如有）：
- 搜索范围：
- 搜索限制：

| 候选 | 核心匹配 | 工程健康 | 许可证/安全 | 证据 | 主要缺口 |
| --- | --- | --- | --- | --- | --- |

- 推荐：直接使用 / 使用并扩展 / 只借鉴 / 自建
- 与上一版决策的变化（如有）：
- 理由：
- 下一步：
```

输出决策后再进入设计或实施；不以“继续搜索”或“稍后收敛”等内部进度状态结束。
