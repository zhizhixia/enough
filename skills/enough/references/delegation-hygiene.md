# 委派卫生

仅在 `enough` 已决定委派子代理、跨角色协作或需要统一回传证据时加载。本参考不替代父级总流程；主代理仍负责编排、授权、整合和独立验收。

## 委派载荷

每项委派只交付一个可独立验收的结果，并明确：

```text
任务：可独立验收的一个结果
父级策略：由 enough 确定；继承，不重跑总流程
风险等级及理由：FAST / NORMAL / DEEP + 具体事实
已授权范围：文件、数据、外部行为边界
验收条件：用户可观察结果及不变项
现有证据：可复用命令、样例、基线或结果
新增永久测试：不需要 / 需要；说明证据缺口
TDD：否 / 仅对指定边界启用；说明理由
验证：本任务相关命令或操作，以及不能验证的部分
禁止操作：未授权 Git 写操作、真实设备/生产接口、部署、发布及其他超出授权的外部写入
返回：实际文件、执行命令与退出码、结果、限制，以及范围或风险变化
```

## 子代理边界

- 继承父级策略、风险、授权、验收和验证选择；不重新进行全局复用研究、设计审批、风险访谈或总流程分流。
- 不擅自扩大文件范围、新增依赖、改变验证政策、接触设备、调用生产接口或执行其他未授权外部操作。
- 发现范围、风险、授权、验收、测试价值或 TDD 边界需要改变时，停止该决策并回报主代理；不得自行批准。
- 完成后返回实际证据，而不是仅声明完成：改动文件、执行命令与退出码、可观察结果、未验证部分和限制。

## 主代理责任

- 子代理的完成摘要不是交付结论。主代理必须检查实际产物，并按已选路径独立验收。
- 已批准的策略在范围未变时沿用；恢复或补充工作从未完成验收项继续，不重开整个流程。
