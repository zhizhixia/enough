# 委派卫生

仅在 `enough` 已决定委派子代理、跨角色协作或需要统一回传证据时加载。本参考不替代父级总流程；主代理仍负责编排、授权、整合和独立验收。

## 委派载荷

每项委派只交付一个可独立验收的结果，并明确：

```text
任务：可独立验收的一个结果
父级策略：由 enough 确定；继承，不重跑总流程
风险等级及理由：FAST / NORMAL / DEEP + 具体事实
工作目录与基线：绝对路径；委派前差异或文件清单，区分已有修改
已授权范围：可写文件与报告、数据、外部行为边界；其余只读
临时文件：允许的绝对目录及清理范围；不需要则写“无”
只读操作：允许的命令与路径；与禁止 Git 写操作分别说明
验收条件：批准来源、用户可观察结果及不变项；沿用原编号或表述
现有证据：可复用命令、样例、基线或结果
新增永久测试：不需要 / 需要；说明证据缺口
TDD：否 / 仅对指定边界启用；说明理由
验证：本任务相关命令或操作、工作目录，以及不能验证的部分
禁止操作：未授权 Git 写操作、真实设备/生产接口、部署、发布及其他超出授权的外部写入
返回：整个任务的修改、逐项验收、准确命令与退出码、证据位置、限制与偏离
```

## 子代理边界

- 继承父级策略、风险、授权、验收和验证选择；不重新进行全局复用研究、设计审批、风险访谈或总流程分流。
- 不擅自扩大文件范围、新增依赖、改变验证政策、接触设备、调用生产接口或执行其他未授权外部操作。
- 发现范围、风险、授权、验收、测试价值或 TDD 边界需要改变时，停止该决策并回报主代理；不得自行批准。
- 临时文件也受授权范围约束。追加验证提示与范围冲突时，优先使用范围内的等价验证；无法执行则报告具体阻塞，不自行改用系统 TEMP 或扩大清理范围。

## 整项任务回报

- 最终回报覆盖整个原始委派任务，包括补验证或恢复前已经完成的工作。修改清单以委派前基线到当前产物的实际差异为准；最后一轮未改文件，不等于整项任务没有改动。
- 按原验收项汇总累计证据，以最新证据更新状态：新失败或未解决阻塞必须替换旧的通过结论。保留已有成果，不机械拼接过期摘要；未验证项明确标注。
- 验证记录给出可复跑的准确命令、工作目录、退出码和日志或脚本位置。一次性脚本需清理时，保留必要的脚本或命令原文及输出位置；只有“运行了临时验证脚本”的描述不算可复跑证据。

## 主代理责任

- 派发前固定验收口径和来源；追加检查时说明原因，涉及范围或授权变化先确认，不能悄悄改成原任务的通过条件。审查任务中立列出支持与反对结论的证据，不预设必须通过或必须纠偏。
- 在已有计划或任务书中给每个总验收条件指定负责人和证据位置，无需另建流程；未委派项仍由主代理负责，未执行就保留为未验证。
- 子代理的完成摘要、`completed` 或结构校验通过都不是交付结论。主代理必须检查实际产物，并按已选路径独立验收；摘要与产物冲突时先核对基线、差异和原始记录，再决定补齐或重派。
- 分开记录功能是否满足、授权范围偏离和证据观察限制。功能通过不能抵消越界；无关并发文件变化不能直接归因于本任务，也不作为功能失败的替代证据。
- 已批准的策略在范围未变时沿用；恢复或补充工作从未完成验收项继续，不重开整个流程。
